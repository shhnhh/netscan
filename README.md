# NetScan

Локальный сетевой сканер для iOS (альтернатива Fing без подписки). Находит
устройства в текущей Wi-Fi подсети через TCP ping-sweep и обогащает список
именами через Bonjour/mDNS.

## Как это работает (MVP)

- `NetworkInfo` — читает IP/маску интерфейса `en0` (Wi-Fi) через `getifaddrs`.
- `SubnetScanner` — параллельно (до 32 одновременно) стучится TCP-коннектом
  на несколько частых портов (`80, 443, 22, 445, 62078`) на каждый хост
  подсети; таймаут 0.6с. Отклик (успех или явный `ECONNREFUSED`) считается
  признаком живого хоста. Параллельно с портами на каждый хост шлётся ещё
  и `ICMPPinger` (unprivileged ICMP echo, тот же трюк, что у Apple
  `SimplePing`) — часть устройств (телефоны, IoT) не держит открытым ни
  один из проверяемых портов, но отвечает на пинг; без этого их видно не
  было. Своё устройство в список добавляется сразу, без пробинга — оно и
  так точно "живое".
- Во время скана `ContentView` показывает счётчик "проверено X/Y · найдено N"
  (данные из `SubnetScanner`'s `onProgress`) — иначе непонятно, идёт ли
  скан вообще или он просто ничего не находит.
- `BonjourScanner` — параллельно слушает объявленные mDNS-сервисы
  (`_http._tcp`, `_airplay._tcp`, `_ipp._tcp` и т.д.) для человекочитаемых
  имён устройств.
- SwiftUI: список найденных устройств → детали (IP, порты, отклик).

### Глубокое сканирование и безопасность

Из деталей устройства по кнопке **"Глубокое сканирование"** запускается
отдельный, более тяжёлый проход только по этому хосту:

- `DeepPortScanner` — стучится на ~35 портов (базы данных, RDP/VNC/Telnet,
  RTSP/DVR-порты камер и т.д.), в отличие от `SubnetScanner` считает порт
  открытым только по реальному TCP-хендшейку (не по `ECONNREFUSED`).
- `BannerGrabber` — на открытых портах, где это уместно, делает один запрос
  (для HTTP — `GET /`, для RTSP — `OPTIONS`) и читает первый ответ/баннер.
- `SecurityAnalyzer` — набор простых правил поверх портов/баннеров:
  подсвечивает типичные проблемы конфигурации (открытый Telnet, БД без
  пароля на виду, RDP/VNC в сети и т.п.) и по портам/баннерам (RTSP,
  DVR-порты, строки вида `hikvision`/`dahua`/`dvr`) помечает устройство как
  вероятную камеру/видеорегистратор.

Это **полностью пассивная разведка**: один банер-граб на порт, без подбора
паролей, без эксплуатации найденного и без обращения к самому видео/аудио
потоку камеры. Инструмент для собственной сети — не для чужой.

Отдельно для RTSP-портов (554/8554) баннер-граббер шлёт `DESCRIBE` вместо
`OPTIONS` — по коду ответа (есть `401` или нет) видно, требует ли поток
пароль. Если не требует — это критичная находка в списке проблем
("похоже открыт без пароля"), но само приложение к потоку не подключается
и видео не показывает — только читает один текстовый заголовок ответа.

### Карта сети

Кнопка со значком "точки-линии" в тулбаре (`ContentView`) открывает
`NetworkMapView` — **логическую** топологию сети: роутер в центре, все
найденные устройства лучами вокруг него, линия красная/оранжевая если у
устройства есть critical/warning finding из `SecurityAnalyzer`. Это не
физическое расположение в комнате (см. "Известные ограничения" — iOS не
даёт read RSSI, точная геопозиция по Wi-Fi без спецжелеза невозможна), а
структура подключений — так же как показывает "Network Map" в Fing.
Иконка узла зависит от открытых портов (принтер/камера/iOS-устройство) —
чем больше отработал "Глубокое сканирование" по устройствам, тем точнее
картинка, поскольку часть портов (например RTSP) не входит в быстрый
начальный ping-sweep.

Карта поддерживает **пинч-зум и перетаскивание** (`MagnificationGesture` +
`DragGesture` поверх фиксированного по размеру канваса — не `ScrollView`,
у него нет нативного зума до iOS 17). Раскладка — **концентрические
кольца**, а не один сплошной круг: при сотнях устройств один круг даёт
такой радиус, что от роутера до любого узла — экран за экраном пустоты, и
при открытии карты (центр — роутер) не видно вообще ничего. Кольцами
первые ~14 устройств остаются рядом с роутером сразу, а остальные —
дальше, доступны панорамированием/зумом. При открытии карта **не** пытается
подогнать всё под экран — специально: с 200+ устройствами "всё видно"
означает "один нечитаемый круг из точек", вместо этого сразу центр на
роутере на нормальном масштабе. Подписи с именем/IP скрываются при
уменьшенном масштабе (когда узлов много и текст неизбежно налезет) и
появляются обратно при зуме внутрь.

Зум **привязан к текущей позиции экрана**, не к центру канваса: раньше
`scaleEffect` масштабировал вокруг геометрического центра канваса
(роутера) независимо от того, куда до этого утащили карту перетаскиванием
— пинч визуально "дёргал" картинку назад к роутеру. Формула компенсации
простая: `offset' = offset * (newScale / oldScale)` — при изменении
масштаба в `r` раз панорамирование домножается на тот же `r`, и то, что
сейчас в центре экрана, остаётся в центре экрана.

Важно: `NetworkMapView` **не регистрирует свой** `navigationDestination(for: Device.self)`
— единственная регистрация для `Device` живёт в `ContentView`. Раньше
было по одной в каждом месте, и из-за двух обработчиков одного типа в
одном `NavigationStack` тап по устройству на карте улетал не туда;
`NavigationStack` в SwiftUI ожидает один источник истины на тип, не
несколько.

### Тест скорости сети

Третья кнопка в тулбаре — `SpeedTestView`. `SpeedTestService` гоняет
пинг/скачивание/отдачу против публичных, не требующих ключа эндпоинтов
`speed.cloudflare.com` (`__down`/`__up` — то же, чем пользуется их
собственная страница спидтеста): пинг — медиана трёх HEAD-запросов,
скачивание — до 50 МБ или 6 секунд (что раньше), отдача — 8 МБ случайных
байт (генерятся через `arc4random_buf`, не поэлементным Swift-циклом —
на 8 млн байт это ощутимая разница в скорости генерации).

### MAC-адрес, вендор, платформа, роутер, Wake on LAN

- `NetworkInfo.hostAddresses` раньше **всегда** варьировал только последний
  октет в пределах "своего" /24, даже если реальная маска была шире (/22,
  /21…) — на подсети больше /24 сканировались только первые 254 адреса, а
  всё остальное молча пропадало. Это, скорее всего, и есть главная причина
  расхождения с Fing по числу найденных устройств: теперь честная
  CIDR-арифметика по 32-битному представлению IP/маски, лимит поднят до
  512 хостов.
- `ARPTableReader` читает уже заполненную ядром ARP-таблицу тем же
  sysctl-механизмом, что использует команда `arp -a`
  (`CTL_NET/PF_ROUTE/NET_RT_FLAGS/RTF_LLINFO`) — публичный API без
  привилегий, ничего активно не зондирует, только читает то, что ОС и так
  узнала, отправляя пакеты во время скана. `MacVendorLookup` — небольшой
  захардкоженный OUI-справочник (не полная база IEEE на 40k+ записей, а
  самые частые производители), даёт что-то вроде "Поставщик MAC: Intel"
  из Fing, но не претендует на полноту.
- `PlatformGuesser` — эвристика Apple/Windows/Android по портам
  (62078/7000 → Apple, 3389/NetBIOS+SMB → Windows) и подстрокам в
  Bonjour-имени/hostname. Без TTL-фингерпринтинга и полной OUI-базы это
  грубее, чем у Fing, но с иконками (SF Symbols не даёт логотипы
  Windows/Android — там нейтральные иконки, у Apple логотип есть).
- Роутер получает отдельный, более широкий проб (через `DeepPortScanner`)
  на предполагаемый IP шлюза (первый адрес подсети — эвристика, настоящий
  default route публичным API недоступен) параллельно с общим сканом, и
  явно помечается `isGateway` — раньше он показывался в списке только если
  случайно отвечал на один из 5 портов быстрого свипа.
- `WakeOnLAN` шлёт стандартный magic packet (UDP broadcast на порт 9) по
  MAC — появляется в деталях устройства, если MAC уже известен.
- **Чего нет и не будет**: "Block device"/"Pause internet" (как в Fing) —
  это ARP-spoofing чужого трафика, у Fing это отдельная платная железка
  (Fingbox), а не сама программа с телефона; на iOS это и технически
  недостижимо без джейлбрейка, и по сути уже не сканер, а атака на чужие
  устройства в сети.

### Известные ограничения

- iOS с 14-й версии требует явно перечислять типы Bonjour-сервисов в
  `Info.plist` (см. `NSBonjourServices` в `project.yml`) — сканировать
  вообще все сервисы, как это может делать Fing на настроенном роутере,
  нельзя без этого списка.
- Для первого запуска на устройстве потребуется разрешение
  "Локальная сеть" (сработает автоматически по `NSLocalNetworkUsageDescription`).
- MAC-адрес появляется не сразу и не для всех — только после того, как ОС
  уже обменялась IP-трафиком с хостом и занесла его в ARP-кэш; устройства,
  которые отвечают исключительно на ICMP (не на TCP), могут не попасть в
  таблицу вовремя.

## Сборка (нужен Xcode → значит нужен Mac)

Проект держится как обычные Swift-файлы + `project.yml` для
[XcodeGen](https://github.com/yonaskolb/XcodeGen), а не как бинарный
`.xcodeproj` — так удобно редактировать код где угодно (в том числе тут, в
Linux), а сам `.xcodeproj` генерируется по требованию.

### Вариант A — есть доступ к Mac (свой/чужой/облачный)

```bash
brew install xcodegen
cd appleapp
xcodegen generate
open NetScan.xcodeproj
```

Дальше как обычно: выбираешь свой Apple ID в Signing & Capabilities,
подключаешь iPhone, жмёшь Run.

### Вариант B — совсем без Mac и бесплатно: GitHub Actions

GitHub Actions с macOS-раннером **бесплатен и безлимитен для публичных
репозиториев** (для приватных — урезанная квота из-за x10 множителя на
macOS-минуты). Воркфлоу уже лежит в
[`.github/workflows/build.yml`](.github/workflows/build.yml):
он генерит проект через XcodeGen, собирает архив **без подписи**
(`CODE_SIGNING_ALLOWED=NO`) и упаковывает `.app` в `NetScan-unsigned.ipa`
как build-артефакт — платный Apple Developer аккаунт для этого не нужен.

Чтобы запустить:

1. Запушь репозиторий на GitHub как **публичный**.
2. Вкладка **Actions** → выбери workflow **"Build unsigned IPA"** →
   **Run workflow** (или просто пушь в `main` — триггерится сам).
3. Через пару минут в этом же запуске внизу будет артефакт
   **NetScan-unsigned-ipa** — скачай его, там `NetScan-unsigned.ipa`.
4. Этот неподписанный `.ipa` скармливаешь своему iLoader — он подписывает
   его твоим бесплатным Apple ID локально при установке на телефон (так
   же работают Sideloadly/AltStore). Из-за ограничения бесплатного Apple ID
   приложение придётся переустанавливать/переподписывать раз в 7 дней —
   это ограничение Apple, а не наше, и то же самое было бы с любым другим
   бесплатным способом сайдлоада.

## Дальнейшие шаги

- Резолвить IP из результатов Bonjour и мёржить в общий список устройств
  (сейчас `mergeBonjourName` — заглушка).
- Reverse DNS для `hostname`.
- Пуш-уведомление на "новое устройство в сети" (актуально для домашней
  безопасности — как раз то, за что Fing просит подписку).
- Результаты глубокого скана сейчас живут только в открытом экране деталей
  и не сохраняются обратно в общий список устройств — при повторном заходе
  на устройство скан прогоняется заново.
- Трассировка (traceroute, как в Fing) технически возможна на той же базе,
  что ICMPPinger — увеличивать TTL и ловить ICMP time-exceeded — но не
  сделана: это ещё один раунд низкоуровневого сокет-кода, а его уже
  накопилось прилично для одной сессии без Mac под рукой для локальной
  проверки сборки.
- `MacVendorLookup` — маленький захардкоженный список, не полная база IEEE.
